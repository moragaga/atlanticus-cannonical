# Real READMEs

Estado: **CURRENT DIRECTION**

Durante incrementos parciales se evita crear READMEs que queden obsoletos.

Al estabilizar una capability/process/application sí se crea un README real.

## README mínimo

Debe explicar:

1. propósito;
2. ownership/responsabilidad;
3. dependencias;
4. configuración;
5. env.detail/secrets;
6. cómo ejecutar local;
7. cómo validar;
8. cómo generar artifact;
9. cómo consumir/distribuir;
10. estados/errores importantes;
11. recovery/reprocessing si aplica;
12. ejemplos de uso;
13. límites/no responsabilidades.

## Regla

README no duplica todo el código ni el canonical architecture.

Debe ser suficiente para que un mantenedor pueda operar el componente sin reconstruir su historia.
